# 收入确认核算应用（合同 / 收款 / 履约对照）

帮助财务分清三件事：**签了多少合同**、**收了多少钱**、**当期真正履约确认了多少收入**。
围绕账号订阅、一次性实施、按量服务三类履约义务建立核算，按示例政策分配交易价格、
分别生成确认计划，**不把开票/收款直接当成收入**。

## 技术栈

- **Vue 3**（+ vue-router / Vite）：合同组成及递延余额对照页面
- **Django REST Framework**：全部金额用 `Decimal` 计算
- **PostgreSQL**：保存履约义务、独立售价（SSP）、确认计划与确认依据

## 示例政策（仅用于本项目演示，不宣称覆盖所有会计准则）

1. **分摊**：交易价格按各项履约义务的相对独立售价比例分摊，尾差由最后一行倒挤，
   保证分摊合计 = 合同交易价格。
2. **账号订阅**：服务期覆盖的每个自然月等额确认（直线法，按月），确认动作逐期执行。
3. **一次性实施**：录入验收证据后，在验收所属期间一次性确认；**没有验收证据的实施部分保持待确认**。
4. **按量服务**：分摊单价 = 分摊价 ÷ 预估总量；按已录入用量确认，累计不超过该行分摊价。
5. **收款**：只形成递延（合同负债），绝不直接确认收入。

## 目录结构

```
server/            Django 项目（config=项目配置, revrec=核算应用）
  revrec/models.py     履约义务、独立售价、确认计划、验收证据、用量、收款
  revrec/services.py   分摊与确认的核心核算逻辑（Decimal）
  revrec/management/commands/seed_demo.py   三组虚构案例
client/            Vue 3 前端（构建产物输出到 server/frontend_dist）
scripts/verify_cases.py   三组案例的逐期核对脚本（走 REST API 并断言）
```

## 启动

```bash
./start.sh          # 启动 PostgreSQL + 迁移 + 写入案例 + 构建前端 + 启动 Django
# 打开 http://127.0.0.1:8000/
```

## 逐期核对

```bash
python3 manage.py seed_demo        # 重置案例数据
python3 ../scripts/verify_cases.py # 52 项断言逐期核对
```

## 三组虚构案例

| 案例 | 合同 | 看点 |
| --- | --- | --- |
| 跨月订阅 | HT-2026-001 星辰科技 | 折扣分摊（13500 vs ΣSSP 15000）；订阅 1-6 月每月确认 1800；实施 2 月验收确认 2700 |
| 部分验收 | HT-2026-002 蓝鲸制造 | 模块一 2 月验收确认 18000；模块二无验收证据，9000 始终保持待确认 |
| 预收未开通 | HT-2026-003 云帆贸易 | 2 月全额预收 6800 但订阅 7 月才开通 → 核对期内确认 0；按量 4 月 3000 次确认 600、5 月 2500 次确认 500 |

## 主要 API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/summary/?as_of=YYYY-MM` | 期间×合同确认矩阵；as_of 给时点快照 |
| GET/POST | `/api/contracts/` | 合同列表 / 创建（创建即自动分摊） |
| GET | `/api/contracts/{id}/` | 合同组成、确认计划、递延对照 |
| POST | `/api/contracts/{id}/recognize_period/` | 确认指定期间的订阅计划 |
| POST | `/api/contracts/{id}/payments/` | 登记收款（不确认收入） |
| POST | `/api/lines/{id}/acceptance/` | 录入验收证据 → 实施确认 |
| POST | `/api/lines/{id}/usage/` | 录入用量 → 按量确认 |
